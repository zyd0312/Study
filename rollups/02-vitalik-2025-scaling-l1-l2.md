# 2025 及以后的以太坊 L1 与 L2 扩容（Scaling Ethereum L1 and L2s in 2025 and beyond）

> **作者**：Vitalik Buterin｜**发表日期**：2025-01-23｜**原文链接**：https://vitalik.eth.limo/general/2025/01/23/l1l2future.html
> **一句话结论**：以太坊应当继续坚持以 L2 为主的扩容路线（而不是掉头去堆高 L1 gas limit），但必须让 L2 真正兑现当初的承诺——加速扩容 blob、让 L2 达到分片级别的安全性、把互操作性标准化到"用起来像一条链"、把存取款时间从"周"压到"分钟乃至一个 slot"，同时明确设计 ETH 的价值捕获路径。

## 背景：这篇文章要解决什么问题

这篇文章写于 2025 年初，是 Vitalik 对"以太坊扩容路线到底还走不走 rollup 这条路"的一次正面回应。

背景是：2020 年以太坊确立了「以 rollup 为中心的路线图（rollup-centric roadmap）」，2024 年 EIP-4844（proto-danksharding）上线，L2 生态确实起来了——按文中的数据，L2 把以太坊的交易容量放大了约 17 倍，手续费也下降了同一量级，Base 一家的 TPS 就接近以太坊自身容量的 40%。但同时，模块化路线的副作用开始被大量诟病：几十条 L2 各自为政、资产割裂、跨链体验糟糕、L1 本身的费用收入和 ETH 的价值捕获被质疑。社区里出现了一股"不如放弃 L2，直接把 L1 gas limit 拉高"的声音。

Vitalik 在文章开头先花了不小篇幅讲一个非技术的前提：**以太坊的技术项目和社会项目是缠绕在一起的**。他的原话是「If you have a decentralized technical system at time T, but a centralized social process maintaining it, there is no guarantee that your technical system will still be decentralized at time T+1.」（引用）。这句话是后面所有技术选择的隐含前提：他反对"回到单一 L1"的核心理由，不是 L1 扩不动，而是那样会牺牲掉以太坊现在这套多方并行研发、多家实体各自去找用户的社会结构。

所以文章要回答的其实是两个问题：**路线还走不走 L2？**（答：走）**如果走，L2 现在还欠什么，怎么补？**（这是全文主体）

## 核心内容

### 一、L2 的崛起：已经不是 2019 年的实验品了

Vitalik 先给出正面证据，说明 rollup 路线不是画饼：

- **去中心化程度**：截至写作时，已有 3 个 stage 1 rollup（Optimism、Arbitrum、Ink）和 3 个 stage 2 rollup（DeGate、zk.money、Fuel）。（Stage 0/1/2 是 L2BEAT 的分级：stage 0 基本靠多签，stage 2 才是"训练轮"完全拆掉、纯靠证明系统保安全。）
- **规模**：L2 已经承载数十亿美元资产，扩容 17 倍，费用降到"接近一年时间里都很低"。
- **应用**：DeFi、社交网络（Farcaster、Lens）、预测市场、Worldchain（已 1000 万用户）都跑在上面；连一度被判死刑的"企业链"叙事也借 L2 复活（例子是 Soneium）。

他特别强调这些成绩里有很大一部分是**社会性收益**：以太坊基金会不需要自己去拉所有用户，有几十个独立实体有动机去做这件事，并且它们反过来给协议贡献了关键技术。这是他后面拒绝"回归单一 L1"的论据。

### 二、两大挑战：规模不够，以及异构性带来的协调问题

**挑战 1：规模（scale）。** blob 空间"勉强够今天的 L2 和用例用"，离明天的需求差得远。这是个纯技术问题，方案好描述、难实现：给以太坊更多 blob。

**挑战 2：异构性（heterogeneity）。** 这是全文最重要的一个概念澄清。2017 年的分片（sharding）设想是：一条链里有很多 shard，每个 shard 是 EVM 的一份拷贝，只由一小部分节点处理。**L2 在理论上就是这个方案的一种实现**——但现实里有个关键差别：每个"分片"是不同的主体造的，基础设施把它当成不同的链，标准也各不相同。于是就变成了今天的可组合性（composability）和用户体验问题。

这个类比是理解 Vitalik 全篇要求的钥匙：**他给 L2 定的及格线，就是"2016 年式分片本来会给你的东西"**。凡是原生分片里不会出现的信任假设，今天也不该接受。后面讲桥的时候他会把这句话说得很硬。

第二个挑战本质是**协调问题（coordination problem）**，比 The Merge 更难，因为参与方更多、目标更杂，而且开始得太晚。但他认为生态解决过难题，这次也能。

### 三、为什么不走"放弃 L2、堆高 L1"的捷径

这是文章的路线判断。他承认这是一条"可能的捷径"（无论是单分片还是多分片），但直接否定：**这种做法牺牲掉了以太坊当前社会结构的太多好处**——那套结构同时兼容了不同形态的研究、开发和生态建设文化。

结论是：**坚持原路线，主要通过 L2 扩容，但要确保 L2 真正兑现它承诺的东西。** 随后他列出一份"要做什么"的清单，也就是全文后半段的目录：

1. L1 **加速扩容 blob**。
2. L1 也要**适度扩容 EVM、提高 gas limit**——因为即使在 L2 主导的世界里，L1 仍然要处理一大堆活动：证明的提交、大规模 DeFi、存取款、极端情况下的大规模退出（mass exit）、keystore 钱包、资产发行。（译注：这一条其实是对"L1 完全躺平只做 DA 层"这种理解的纠偏——L1 execution 不能不管。）
3. L2 继续**提升安全性**，把分片本该给的保证（抗审查、轻客户端可验证、没有被写死的受信任第三方）都补上。
4. L2 和钱包**加速互操作性的改进与标准化**。他的原话很直白：「Using Ethereum should feel like using a single ecosystem, not 34 different blockchains.」（引用）
5. L2 的**存取款时间必须大幅加快**。
6. 只要基本互操作需求被满足，**L2 的异构性是好事**：有的会是治理极小化、跑 L1 EVM 精确拷贝的 based rollup；有的会实验不同的 VM；有的更像用以太坊给用户加一层安全保证的服务器。**光谱的每一段都需要有人做。**
7. 要**显式地思考 ETH 的经济学**，确保在 L2 主导的世界里 ETH 仍然能积累价值。

### 四、扩容：blob，blob，还是 blob

技术账算得很具体：

- EIP-4844 之后每 slot 有 3 个 blob，即每 slot 384 kB 数据带宽 ≈ 每秒 32 kB。一笔交易上链约 150 字节，于是约 **210 TPS**——L2BEAT 的实测数据几乎正好是这个数。
- **Pectra**（计划 3 月上线）把它翻倍到每 slot 6 个 blob（EIP-7691）。
- **Fusaka** 的目标是主攻 **PeerDAS**（一种基于成熟 p2p 组件的数据可用性采样方案），理想情况下这个分叉里除了 PeerDAS 和 EOF 别的都不放。PeerDAS 可以立刻再提升 2-4 倍，之后随时间提升到 8 倍以上。
- 再往后是 **2D 采样（2D sampling）**，可以做到每 slot 128 个 blob，加上数据压缩的改进，最终能到 **10 万 TPS 上链**。

以上都还是"2025 年之前就有的既定路线图的复述"。Vitalik 自己认为**真正的新问题是：怎么让它更快发生**。他的答案有四条：

1. **更愿意显式地给"非 blob"的特性降优先级。**（这是很强的表态：分叉的资源要向 blob 倾斜。）
2. 把"blob 是目标"讲得更清楚，并把相关的 **p2p 网络研发当成人才招募的优先项**。
3. **让 blob target 可以由质押者直接调整**，就像 gas limit 一样——这样 blob 上限就能随技术进步快速上调，**不用等硬分叉**。
4. 可以*考虑*一些更激进的方案：以对低资源质押者引入更多信任假设为代价，更快拿到更多 blob——但他明确说对此要小心。

（译注：第 3 条在治理上很关键，等于把 DA 容量的调节权从"硬分叉流程"下放到"质押者的实时旋钮"。）

### 五、提升安全性：证明系统与 native rollup

现状是个尴尬的事实：**大部分活动仍然发生在 stage 0 rollup 上，也就是多签（multisig）**。他说这必须改。而之所以改得慢，根本原因是——「building a proof system, and getting enough confidence in it to be willing to give up training wheels and rely fully on it for security, is hard.」（引用）造证明系统难，敢于把训练轮拆掉、把安全性完全托付给它，更难。

他给出两条并行的路：

**路线 A：Stage 2 + 多证明者（multi-provers）+ 形式化验证（formal verification）。** 用多个证明系统互为冗余，再用形式化验证（如 verified ZK-EVM initiative）来建立对它们的信心。这条路的路线图相对清楚，能加速的地方主要是**在软件栈上更多地合作**，减少重复劳动，顺便还能收获互操作性。

**路线 B：native rollup（原生 rollup）。** 把 EVM 状态转移函数的验证**做进协议本身**，比如做成一个 precompile（预编译合约）。这样 L2 不用自己造 ZK-EVM 证明系统，直接调用 L1 提供的"验证一段 EVM 执行"的能力。

他强调 native rollup 还是很早期的想法，有大量思考要做，核心难点是：**怎么让这个 precompile 尽可能灵活。** 理想目标不只是支持 EVM 的精确克隆，还要支持带各种改动的 EVM——让一个改过 EVM 的 L2 仍然能用这个 native rollup precompile，只需要"为自己的改动自带 prover"。这个思路可以应用到 precompile、opcode、状态树等部件上。

（批注：native rollup 是这篇文章里最有"新意"的技术方向。它其实是在回答一个老问题——如果 L2 最终都要跑 EVM，那每家自己造一套 ZK-EVM 电路是巨大的重复劳动和重复风险面；不如把它 enshrine 进 L1。代价是牺牲一部分 L2 的自主性，而"自带 prover 处理增量改动"就是他给出的折中。）

### 六、互操作性与标准

目标一句话：**在不同 L2 之间转移资产、使用应用，体验要跟它们是同一条链的不同 shard 一样。** 他说这份路线图其实已经清楚了好几个月：

- **链特定地址（chain-specific addresses）**：地址里要同时包含"链上的账户"和"链本身的标识符"。ERC-3770 是早期尝试，现在有更成熟的想法，还会把 L2 的注册表（registry）搬到 L1 上。
- **标准化的跨链桥与跨链消息传递**：要有标准的方式去验证证明、传递消息，而且这些标准**除了 L2 自身的证明系统之外不应该要求信任任何东西**。这里他态度最硬：「An ecosystem relying on multisig bridges is NOT acceptable.」（引用）判据就是前面那把钥匙——**如果这个信任假设在 2016 年式分片里不会存在，那今天就不可接受，没得商量。**
- **加快存取款时间**：让"原生"消息从几周变成几分钟，最终变成一个 slot。这需要更快的 ZK-EVM prover 和证明聚合（proof aggregation）。
- **从 L2 同步读取 L1 状态（synchronous read of L1 from L2）**：如 L1SLOAD、REMOTESTATICCALL。这让跨 L2 互操作大大简化，也有利于 keystore 钱包。
- **共享排序（shared sequencing）** 等更长期的工作。**based rollup** 的价值之一就在于它可能能更有效地做到这件事。

只要这些标准被满足，L2 之间仍然可以差别很大——不同的虚拟机、不同的排序模型、不同的"规模 vs 安全"取舍都可以。**但用户和应用开发者必须清楚地知道自己拿到的是什么级别的安全性。**

他还提了一条推进策略：很大一部分工作可以由**跨生态的实体**（以太坊基金会、客户端团队、主要应用团队）来做，这样单个 L2 和钱包要做的工作就变少，采纳标准就成了"不用想的事"（no-brainer）。但最后一公里——真正实现并交付给用户——还是得 L2 和钱包自己上。

### 七、ETH 的经济学

这一节回应"L2 吸血 L1"的批评。框架是把 ETH 当作**三态资产（triple-point asset）**：既是储备资产、又是可质押的收益资产、又是消耗性商品（gas）。策略要"多管齐下"，覆盖 ETH 价值的各种可能来源：

1. **广泛达成共识，把 ETH 确立为整个（L1 + L2）以太坊经济体的主要资产**，支持应用把 ETH 当作主要抵押品。
2. **鼓励 L2 拿出一定比例的费用来支持 ETH**：可以是烧掉一部分费用，可以是永久质押并把收益捐给以太坊生态公共品，也可以是别的公式。
3. **支持 based rollup，把它作为 L1 通过 MEV 捕获价值的一条路径**——但不要试图强迫所有 rollup 都变成 based（因为并非所有应用都适用），也**不要以为光靠这个就能解决问题**。
4. **提高 blob 数量**，考虑设置 blob 的最低价格，把 blob 也当作一个潜在收入来源。他给了个算术示例：如果取过去 30 天的平均 blob 费用，并假设它在 blob 数量涨到 128 时因为**诱导需求（induced demand）**而保持不变，那么以太坊每年会销毁 **71.3 万 ETH**。但他紧接着自我设限：**这么好的需求曲线并没有保证，同样不要以为光靠这个就能解决问题。**

（批注：这一节的写法值得注意——四条里有两条他都主动加了"不要指望这一条就够了"。这是把 ETH 价值捕获当作一个**尚未解决的开放问题**在处理，而不是宣布已有答案。）

### 八、结论

以太坊作为技术栈和社会生态都已成熟，但"现在是加倍投入的时候"。他给三类人派任务：L2 开发者去贡献 blob 安全扩容的工具、EVM 执行扩容的代码、互操作的标准；钱包开发者去实现这些标准，让生态"在用户看来无缝，同时保持以太坊还只是一条 L1 时那样的安全和去中心化"；ETH 持有者和社区成员去积极参与讨论，因为很多领域仍然需要主动的思考和头脑风暴。

## 与 2021 年 Deribit 那篇的关系

Benjamin Simon 那篇写于 2021 年 5 月，核心是 Optimistic vs ZK 的二选一。五年后回看，这篇 Vitalik 的文章基本上是**从那场辩论的"结束之后"开始写的**。

**印证了的：**

- **"长期看两条路的成本/速度/体验会趋近，只剩安全假设和网络效应"** —— 这个判断被验证得相当准。Vitalik 全文没有花任何篇幅争论"Optimistic 好还是 ZK 好"，他谈的是 stage 0/1/2 的**安全分级**、多证明者、形式化验证。也就是说，**竞争维度确实从"技术路线"迁移到了"安全假设"**，正如 Simon 预测的那样。
- **"ZK 的挑战是工程而非理论"** —— 2021 年 ZK 做不出通用 EVM；2025 年 ZK-EVM 已经是既成事实，Vitalik 谈的是"怎么让 ZK-EVM prover 更快、怎么做证明聚合把提款时间压到一个 slot"，而不是"能不能做出来"。
- **"Optimistic 的 1-2 周挑战期是真痛点"** —— Vitalik 把"存取款时间从周变成分钟乃至一个 slot"单列为一条必办事项，等于官方确认这是必须消灭的缺陷；而消灭它的手段正是 ZK（更快的 prover + 证明聚合）。**换句话说，Simon 眼中 ZK 的理论优势，最终变成了整个生态的收敛目标。**

**超越 / 改写了的：**

- **问题的层级变了。** 2021 年的问题是"单条 rollup 怎么做才安全、才可用"；2025 年的问题是"**几十条 rollup 之间怎么才像一条链**"。异构性、链特定地址、跨链消息标准、共享排序——这一整套议题在 2021 年那篇里几乎不存在。**Rollup 的成功本身制造了新的、更难的协调问题。**
- **对"n 中有 1 个诚实"和"单一 relayer"那组安全性对比，Vitalik 给了一个更高的统一标准**：不是比较两种 rollup 谁的假设更弱，而是拿"**2016 年式原生分片本来会给你什么**"当基准线。凡是原生分片里不会有的信任假设，一律不接受——这直接判了 multisig 桥的死刑，也解释了为什么"大部分活动还在 stage 0 rollup 上"被他视为必须改变的现状。
- **一个 2021 年完全没预见的新维度：ETH 的价值捕获。** Simon 的文章里，rollup 只是扩容技术；到 2025 年，"L2 是否在吸 L1 的血"成了必须正面回答的经济学问题，Vitalik 专门开了一节讨论烧费用、based rollup + MEV、blob 收入。**扩容方案的选择变成了货币政策问题。**
- **native rollup 是一个 2021 年思维框架之外的解。** 当年的框架是"L2 各自造证明系统，然后我们比较谁的信任假设更好"；native rollup 说的是"**别各造了，让 L1 直接提供 EVM 验证能力**"——这实际上是在往回收敛，让 L2 更接近它本来该是的东西：分片。

**没有被推翻但被重新加权的：** Simon 认为网络效应会是最终的差异化因素。这一点在 Vitalik 这里被**主动对抗**了——整节"互操作性与标准"的目的，恰恰是**消解单条 L2 的网络效应护城河**，让用户在链之间流动无摩擦。Vitalik 想要的是网络效应属于以太坊整体，而不是属于 Base 或 Arbitrum。

## 值得记住的要点

- **路线判断：不掉头。** 拒绝"放弃 L2、堆高 L1 gas limit"的捷径，理由主要不是技术，而是那会毁掉以太坊多方并行研发的社会结构。但 L1 仍要适度扩容 EVM 和 gas limit，因为证明提交、大规模 DeFi、存取款、mass exit、keystore 钱包这些活动永远得留在 L1。
- **扩容的唯一重点是 blob。** 3 blob（≈210 TPS）→ Pectra 6 blob → Fusaka 的 PeerDAS 再 2-4 倍 → 2D 采样 128 blob → 配合压缩最终 10 万 TPS。加速手段包括：显式给非 blob 特性降优先级、把 p2p 研发当招人重点、**让质押者能像调 gas limit 一样直接调 blob target，从而绕开硬分叉流程**。
- **及格线是"2016 年式分片"。** 这是全文最锋利的判据：任何在原生分片里不会存在的信任假设，今天都不可接受——所以 multisig 桥「NOT acceptable」，所以"大部分活动仍在 stage 0 rollup（即多签）上"必须改变。
- **安全性有两条并行的路**：stage 2 + 多证明者 + 形式化验证（路线清楚，靠软件栈合作提速）；以及 native rollup（把 EVM 验证 enshrine 进 L1 协议，L2 只为自己的改动"自带 prover"，尚属早期）。
- **互操作性的目标是"感觉像一个生态，不是 34 条链"**：链特定地址、无需额外信任的跨链消息标准、把提款压到分钟/单 slot、L2 同步读 L1（L1SLOAD 等）、共享排序。**在此之上，L2 的异构性是好事**——从 based rollup 到实验性 VM 到"加了安全保证的服务器"，光谱的每一段都需要有人做，前提是安全等级对用户透明。
- **ETH 价值捕获是公开的未解问题。** 四条策略（ETH 作为 L1+L2 经济体的主资产、L2 分成/烧费、based rollup 捕获 MEV、blob 收入 + 最低 blob 价格）里，他对其中两条主动加了"别指望光靠这个就够"的免责声明——这是一个诚实标注不确定性的章节，而不是结论。
